Спецификация: Масштабирование баз данных (scaling.md)
### 1. Стратегия масштабирования по сервисам
### 1.1. Сервис финансов (Financial Service DB)
Тип нагрузки: Интенсивная запись транзакций (Write-Heavy), критически важна точность.
Стратегия масштабирования: шардирование
Ключ шардирования (если применим): advertiser_id (Идентификатор рекламодателя)
### 1.2. Сервис ставок (Binding Service — Redis)
Тип нагрузки: Экстремально высокая нагрузка на чтение (Read-Heavy) на 50 000+ RPS.
Стратегия масштабирования: Репликация по схеме Master-Slaves (один узел Master для записи, множество узлов Read-Replicas для чтения).

### 1.3. Сервис кампаний (Campaign Service DB)
Тип нагрузки: Низкая нагрузка, редкие CRUD-операции из админки.
Стратегия масштабирования: Минимальная репликация Master-Slave (1 Master для записи + 1 Read-Replica).

### 1.4. Сервис статистики и Аналитики (CQRS-контур)
* **Паттерн CQRS (Разделение ответственности):** 
  Потоки данных полностью разделены на уровне независимых сервисов и хранилищ. 
  - Поток Записи (Commands) инкапсулирован в связке Binding Service ➡️ Apache Kafka ➡️ Statistics Service ➡️ Statistics DB. Сюда со скоростью Hot Path сливаются сырые логи показов.
  - Поток Чтения (Queries) изолирован в рамках Analytics Service ➡️ ClickHouse.
  - Запросы пользователей на построение отчетов идут в выделенную колоночную базу данных, никак не пересекаясь с транзакционной базой статистики и не создавая взаимных блокировок.

* **Масштабирование ClickHouse:** 
  Используется встроенный кластерный механизм Шардирования и Репликации (Distributed Tables).
  - Данные логов автоматически шардируются (горизонтально режутся) по серверам кластера по ключу `campaign_id` или `timestamp`, что позволяет параллельно выполнять тяжелые агрегационные запросы силами всех узлов.
  - Каждый шард снабжается локальной синхронной репликой для обеспечения отказоустойчивости (High Availability) на случай сбоя железа.
  - Выделение отдельных read-реплик для аналитики не требуется, так как ClickHouse изначально спроектирован для высокопараллельного чтения терабайтных массивов.
