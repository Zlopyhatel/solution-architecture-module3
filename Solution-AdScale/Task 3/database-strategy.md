Сервис										              Тип базы данных							          Обоснование
Сервис ставок (Binding Service)				  In-Memory Key-Value NoSQL (Redis)		Хранит все данные строго в оперативной памяти (RAM) сервера. Из-за этого у неё нет задержек на обращение к диску
Сервис кампаний (Campaign Service)			Реляционная (PostgreSQL)						  Обеспечивает реляционную структуру данных для личного кабинета и поддержку транзакций при ручном редактировании настроек. Нагрузка низкая.
Сервис статистики (Statistics Service)	Реляционная (PostgreSQL)						  Служит приемником для Kafka Connect, куда пачками сливаются агрегированные данные о показах и кликах. Оптимизирована под высокую скорость линейной записи.
Сервис аналитики (Analytics Service)		Колоночная (ClickHouse)					      Сжимает данные логов в 5–10 раз сильнее и выполняет аналитические SQL-запросы в сотни раз быстрее, чем традиционные NoSQL базы
Сервис финансов (Financial Service)			Реляционная (PostgreSQL)						  Важна строгая консистентность, изоляция транзакций и надежность для управления балансами и кошельками. Исключает риски double-spending (перекрута бюджетов).
