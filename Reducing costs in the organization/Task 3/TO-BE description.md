# Механизм обеспечения автономности и синхронизации данных (Offline-mode Strategy)
При первичной инициализации или плановом обновлении торговый планшет обращается через облачный API Gateway к центральным системам (Каталог, Promo Engine), 
скачивая в локальное энергонезависимое хранилище браузера (IndexedDB/кэш) актуальный профиль магазина. 
Этот профиль включает в себя оптимизированную легковесную номенклатурную матрицу, правила расчета базовых скидок и необходимые конфигурации для локального слоя HAL. 
В случае деградации основного проводного канала связи, планшет бесшовно переключается на резервный беспроводной канал (LTE/Wi-Fi). 
С точки зрения кассира и бизнес-процесса, архитектура сохраняет полноценный онлайн-режим работы, продолжая маршрутизировать транзакции эквайринга через облачный Payment Gateway. 
При наступлении полного офлайна (отсутствие всех каналов связи) система автоматически переходит в изолированный гибридный режим. 
Оплата банковскими картами блокируется на уровне интерфейса, однако касса сохраняет 100% автономность для наличного расчета. 
Поиск товаров, применение маркетинговых акций и расчет итоговой стоимости чека выполняются локально на основе ранее закэшированных в памяти планшета данных. 
Сформированные чеки подписываются в фискальном накопителе ККТ и встают в отказоустойчивую локальную очередь на планшете. 
После восстановления связи HAL и кассовое веб-приложение инициируют процедуру фоновой синхронизации. Накопленные за время офлайна чеки пакетами отправляются в облачный бэкенд. 
Чтобы избежать дублирования данных при нестабильном сигнале, отправка чеков защищена сквозными уникальными идентификаторами (паттерн идемпотентности). 
Параллельно с этим планшет актуализирует локальные остатки товаров и затягивает из облачного хранилища обновленные версии прайс-листов, конфигураций и драйверов оборудования, 
возвращая магазин в эталонное состояние онлайн-синхронизации.
